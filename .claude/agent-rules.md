# 에이전트 규칙 (Agent Rules)

이 문서는 AI 에이전트(Claude 등)가 `making` 프로젝트에서 작업할 때
지켜야 할 행동 규칙을 정의합니다.

## 1. 기본 원칙

- **행동 우선**: 충분한 정보가 있으면 되묻지 말고 실행합니다.
- **불필요한 재확인 금지**: 이미 확정된 결정을 다시 논의하지 않습니다.
- **간결한 소통**: 하지 않을 선택지를 장황하게 나열하지 않습니다. 추천안을 제시합니다.
- **한국어 응답**: 사용자가 한국어로 물으면 한국어로 답합니다.
- **정직한 보고**: 실패·생략·미검증 사항을 숨기지 않고 그대로 알립니다.
- **코드베이스 기준 답변 (필수)**: 감·추측으로 답하지 않습니다. 반드시 실제 파일과
  코드를 직접 확인한 뒤 확실한 근거를 가지고 답합니다. 확인이 안 된 내용은
  "확인 안 됨"이라고 밝히고, 추측을 사실처럼 말하지 않습니다.

## 2. 작업 순서

1. **파악**: 관련 파일과 기존 패턴을 먼저 읽습니다.
2. **계획**: 다단계 작업은 짧게 계획을 세운 뒤 진행합니다.
3. **구현**: [project-rules.md](./project-rules.md)의 코딩 규칙을 따릅니다.
4. **검증**: 변경이 실제로 동작하는지 확인합니다.
5. **보고**: 무엇을 왜 바꿨는지 간결하게 설명합니다.

## 3. 확인이 필요한 경우 (먼저 물어보기)

- 되돌리기 어렵거나 외부로 나가는 작업 (배포, 삭제, 전송, 공개)
- 파일 삭제·덮어쓰기 (특히 에이전트가 만들지 않은 파일)
- 아키텍처를 바꾸는 큰 결정
- 요청만으로 판단이 안 서고, 코드나 상식적 기본값으로도 해결 안 될 때

> 그 외에는 합리적 기본값을 선택해 진행하고, 무엇을 선택했는지 응답에 밝힙니다.

## 4. 도구 사용 규칙

- 파일 검색·편집은 전용 도구를 우선 사용합니다 (`cat`/`sed`/`echo` 남용 금지).
- 서로 의존 없는 작업은 한 번에 병렬로 실행합니다.
- 여러 파일을 훑어야 하는 조사는 서브에이전트에게 위임하고 결론만 받습니다.
- 임시 파일은 프로젝트를 어지럽히지 않도록 스크래치 디렉토리를 사용합니다.

## 5. 하지 말아야 할 것

- 요청하지 않은 대규모 리팩터링을 임의로 수행
- 비밀키·민감정보를 로그나 커밋에 노출
- 검증 없이 "완료" 보고
- 사용자가 거절한 방식을 그대로 재시도

## 6. 서브에이전트 / 위임

- 광범위한 검색은 `Explore` 또는 `general-purpose` 에이전트에 위임합니다.
- 독립적인 여러 작업은 한 메시지에서 동시에 실행합니다.
- 위임한 검색을 본인이 중복 수행하지 않습니다.

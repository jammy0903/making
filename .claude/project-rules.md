## 4. 코딩 규칙

- **일관성 우선**: 주변 코드의 네이밍, 들여쓰기, 주석 밀도, 관용구를 그대로 따릅니다.
- **네이밍**: 의미가 드러나는 이름을 사용하고, 축약은 팀에서 통용되는 것만 사용합니다.
- **주석**: "무엇"이 아니라 "왜"를 설명합니다. 자명한 코드에는 주석을 달지 않습니다.
- **파일 크기**: 하나의 파일/함수는 하나의 책임만 갖도록 작게 유지합니다.
- **에러 처리**: 조용히 삼키지 않습니다. 실패는 로그 또는 예외로 드러냅니다.
- **하드코딩 금지**: 설정값·비밀키는 환경변수/설정 파일로 분리합니다.

## 5. Git 규칙

- **브랜치**: 매번 새 브랜치를 만들지 않습니다. 웬만하면 `main`에서 바로 작업합니다.
  별도 브랜치는 사용자가 명시적으로 요청할 때만 만듭니다.
- **커밋 메시지**: 명령형 현재 시제. 예) `add login form`, `fix null check`
- **커밋 단위**: 하나의 논리적 변경 = 하나의 커밋.
- **커밋/푸시**: 사용자가 명시적으로 요청할 때만 수행합니다.

## 6. 보안 규칙

- 비밀키·토큰·비밀번호를 코드나 커밋에 포함하지 않습니다.
- `.env` 등 민감 파일은 `.gitignore`에 추가합니다.
- 외부 서비스로 데이터를 보내기 전 사용자에게 확인합니다.

## 7. 테스트 & 검증

- 변경 후에는 실제로 동작하는지 확인합니다 (테스트 통과만으로 끝내지 않음).
- 테스트가 실패하면 그 사실과 출력을 그대로 보고합니다.
- 완료·검증된 작업만 "완료"라고 보고합니다.

# 공감 리그 · 설계 문서 v4 (최종 통합본)

> **최종 목표는 커뮤니티다.**
> 리그는 그 커뮤니티를 **살아있게 태어나게 하는 장치**다.
>
> 이 문서가 v3 / v3.1 / v4 초안을 모두 대체한다.
> UX 세부는 `공감리그_UX설계문서_v2` 참조.

---

## 1. 정체 — 왜 게시판부터 열면 안 되는가

**새 커뮤니티가 죽는 이유는 딱 하나 — 도착했는데 할 게 없어서.**
글이 없고, 사람이 없고, 아무도 내 글을 안 본다. 그래서 나가고, 그래서 더 텅 빈다.

**리그는 사람이 0명이어도 돌아간다.** 혼자 와도 당장 투표할 게 있다.

```
게임(리그) → 콘텐츠가 쌓임 → 사람이 모임 → 저절로 떠듦 → 커뮤니티
```

> **순서를 바꾸면 둘 다 죽는다.** 도구를 보고 오게 하고, 사람 때문에 남게 한다.

### 🚫 자유 게시판은 마지막에 연다

열면 **전부 거기로 간다.** 아무 말이나 쓰는 게 형식 맞춰 제보하는 것보다 100배 쉽기 때문이다.
그러면 리그는 텅 비고, 남는 건 **개드립 하위호환 게시판 하나**다. 그건 이미 진 싸움이다.

## 2. ⭐ 리그 = 게시판

```
일반 커뮤니티:  글 목록 → 정렬 = 시간순   → 새벽에 올린 명작이 묻힌다
공감 리그:      랭킹    → 정렬 = 공감도   → 좋은 게 떠오른다
```

**랭킹이 곧 피드다.** 커뮤니티를 나중에 "추가"하는 게 아니라, **처음부터 커뮤니티인데 정렬이 특이한 것**이다.

| 커뮤니티 개념 | 이 사이트에서 |
|---|---|
| 게시판 | **리그(축)** |
| 글 목록 | **랭킹** |
| 글 | **상황(Situation)** |
| 댓글 | **이어쓰기(Reply)** |
| 추천 | **1대1 대결(Match)** |
| 작성자 | **최초 제보자** |
| 베스트 댓글 | **승격** — 독립 글이 된다 |

### 축은 '주제'가 아니라 '형용사'다

| ❌ | ✅ |
|---|---|
| 음식 / 영화 / 게임 갤러리 | **제일 짜증나는 순간** |
| (뭘로 1위? 취향이라 순위가 안 나옴) | **제일 킹받는 / 서러운 / 소름 돋는 순간** |

축이 있어야 1대1 비교가 되고 → 랭킹이 되고 → 리그가 된다.

## 3. 화면 구조

### 3-1. 🏠 홈 = 리그 목록
축이 1개일 땐 **홈을 건너뛰고 그 리그로 리다이렉트**한다. (빈 목록 = 죽은 사이트)

### 3-2. 🏟️ 리그 홈 = 대결 위젯 + 피드

```
┌───────────────────────────────────────┐
│  😤 제일 짜증나는 순간                  │
│                                       │
│  ⚔️ 지금 대결 중                       │
│  ┌──────────┐   ┌──────────┐          │
│  │ 라면에    │VS │새끼발가락 │          │  ← 여기서 바로 투표
│  │ 수프 없음 │   │ 찧기      │          │
│  └──────────┘   └──────────┘          │
│           [ 대결 시작 → ]               │  ← 전체화면 몰입 모드
├───────────────────────────────────────┤
│  🔥 오늘  |  🏆 현역  |  🏛️ 전당        │  ← 기본 탭 = 🔥 오늘
├───────────────────────────────────────┤
│  🆕 오늘 데뷔                          │
│  📈 상승세                             │
│  👑 왕좌 방어 3일차                     │
└───────────────────────────────────────┘
```

**첫 화면에서 투표도 되고 커뮤니티도 보인다.**
(v3의 "랜딩 = 첫 대결"은 단일 게임 전제였다. **폐기.**)

### 3-3. ⭐ 피드 3탭 — 고인물 방지의 정답

| 탭 | 정렬 | 성격 |
|---|---|---|
| **🔥 오늘** (기본) | **24시간 ΔElo** + 오늘 데뷔 고정 슬롯 | **매일 완전히 바뀐다** |
| 🏆 현역 | Elo | 안정적. 자주 안 바뀜 |
| 🏛️ 전당 | 헌액순 | 영구 기록 |

> **레딧식 Time Decay를 Elo에 걸면 안 된다** (→ 5-5). 대신 **"상승세"라는 별도 정렬**을 만든다.
> 그러면 Elo는 순수하게 유지되면서 **첫 화면은 매일 새로 바뀐다.**

### 3-4. 📄 상황 상세 = 게시글

```
🥇 1위  "라면 물 다 맞췄는데 봉지에 수프가 없을 때"
        최초 제보 @재미잼 · 47명이 같은 상황 제보
        Elo 1842 · 63승 12패 · 스킵률 8%

💬 이어쓰기 12
   "근데 그게 마지막 라면일 때"      👍 891  [🚀 승격]
```

### 3-5. 🔗 딥링크 (필수)
**모든 공유·유입 링크는 리그 단위 URL.** 재방문 시 마지막 리그를 기억한다.

## 4. ⚔️ 투표

### 4-1. 승자 잔류 (King of the Hill)
이긴 상황이 잔류, 도전자 1장만 교체. **최대 5연승 후 강제 교체.**

| | 새로 읽는 개수 |
|---|---|
| 순진한 페어링 | 20판 × 2 = 40개 |
| **승자 잔류** | 2 + 19 = **21개** |

**읽기량 절반. 체감 30초.** 덤으로 **연승 드라마.**

### 4-2. 🚨 반드시 함께 넣을 보정 3종
**안 하면 랭킹 데이터를 통째로 버리게 된다.**

| 편향 | 대응 |
|---|---|
| 위치 편향 | 매 판 **좌우 랜덤 스왑** + 로그 |
| 친숙성 편향 (잔류가 유리) | **β 보정**: `β = −400·log10(1/p−1)`, 매주 재추정 |
| 반복 판정 | **가중치 감쇠** `w = 1/√k` |

### 4-3. "안 겪어봤어요" 버튼

| 버튼 | 허용 | 이유 |
|---|:--:|---|
| **"이건 안 겪어봤어요"** | ✅ | **Elo 계산에서 완전 제외** |
| ~~"둘 다 짜증나요"~~ | ❌ | 무승부는 30~40%가 **도피처로 쓴다.** 데이터 증발 |

**강제 선택이 이 게임의 심장이다.**

### 4-4. ⭐ 스킵률 = 두 번째 축

```
스킵률 = 안 겪어본 사람 비율 = 보편성의 반대
```

| | Elo 높음 | Elo 낮음 |
|---|---|---|
| 스킵률 낮음 | 🏆 **국민 짜증** — 진짜 1위 | 흔하지만 참을 만함 |
| 스킵률 높음 | 💀 **극한 짜증** — 겪은 사람만 안다 | 죽은 항목 |

**랭킹이 두 개가 되고, 콘텐츠·유튜브 소재가 두 배가 된다.**

### 4-5. 재노출 정책 (완화됨)

```
❌ 재방문 시에도 본 상황 영구 제외      ← 과했다. 소진이 너무 빠름
✅ 세션 내 금지 + 24시간 내 우선순위 하락 (완전 배제는 안 함)
✅ 같은 대진(A vs B)은 30일간 재출현 금지
```

> **문장은 마르지만 대진은 안 마른다.** 상황 300개 → 가능한 대진 **44,850개**.
> 유저가 지겨워하는 건 같은 문장을 또 보는 것이지, 같은 대진이 아니다.

### 4-6. 세션
5판 단위 진행바 → *"계속?"* · 매 표마다 즉시 보상 · 스와이프/방향키 · 되돌리기 1회 · 워밍업 정렬(첫 3판 30자 이하)

## 5. 🏆 랭킹 산식 (확정 스펙)

> **Elo는 실시간 전광판, Bradley–Terry가 공식 순위다.**
> 낮 동안 Elo가 흔들려도 매일 밤 BT가 전부 재계산한다. **그래서 K를 공격적으로 써도 된다.**

### 5-1. 초기 Elo = **1500 고정**

```
초기값 1500 고정   → 30전 후 편향 +3.4    ✅
초기값 풀 중앙값   → 30전 후 편향 +20.3   ❌  (편향 6배)
```

풀 중앙값을 주면 **신인을 과대평가**한다. 신인의 실제 실력 분포는 평균 1500이기 때문이다.
(시뮬레이션 4,000회 기준)

### 5-2. K-factor

```
K(n) = clamp( 64 / (1 + n/12),  10,  64 )

n=0   → 64    첫 판은 크게 튄다 (신인 위치를 빨리 잡는다)
n=10  → 35
n=30  → 18
n=100 → 12
n=∞   → 10    하한. 0으로 가면 오래된 항목이 영영 못 움직인다
```

**수렴 성능 (신인의 평균 오차, Elo)**

| K 스케줄 | 10전 | 30전 | 60전 |
|---|---|---|---|
| **감쇠 64/(1+n/12)** | 98 | 60 | 42 |
| 계단 48→16 | 101 | 58 | 40 |
| 고정 32 | 113 | 65 | 45 |
| 고정 16 | 134 | 93 | 57 |

성능은 계단과 거의 같지만, **연속 감쇠 + 하한**이 고인물을 안 굳게 한다.

### 5-3. 🚨 매칭은 절대값이 아니라 **백분위**

```
❌ |R_i − R_j| < 150 Elo
✅ 백분위 차이 15%p 이내
```

**이게 풀 인플레이션 방어의 핵심이다.** (→ 5-4)
추가로 신규 노출 보장: `가중치 ∝ 1/(1+대결수)` · **20% 완전 랜덤** (그래프 연결성)

### 5-4. 🔴 풀 인플레이션 — 반드시 막아야 하는 것

**하위 30% 탈락 제도가 풀 중앙값을 계속 밀어올린다.** (시뮬레이션)

```
세대1  본선 풀 중앙값 1529
세대3  본선 풀 중앙값 1623
세대6  본선 풀 중앙값 1686   ← 멈추지 않는다
```

약자가 잘려나가니 살아남은 풀이 계속 강해진다. 그런데 신인은 1500으로 들어온다.
→ **6세대만 지나면 신인이 풀 중앙값보다 186점 아래에서 출발한다.**

**방어 2중**
1. **백분위 매칭** (5-3) — Elo 절대값이 부풀어도 신인은 항상 자기 수준의 상대를 만난다
2. **주간 재정규화** — BT 재추정 후 **전체 평균을 1500으로 되돌린다**
   (안 하면 3개월 뒤 1위가 2400점인데 그게 무슨 의미인지 아무도 모른다)

### 5-5. 🚫 Elo에 Time Decay를 걸지 않는다

| | 레딧 | **우리** |
|---|---|---|
| 점수 | 누적 추천 (계속 쌓임) | **Elo = 상대 강도 측정값** |
| 오래된 글이 1위인 이유 | 시간이 지나며 표가 쌓여서 | **진짜로 계속 이겨서** |
| 처방 | 감가상각 필요 | **감가상각하면 측정이 망가진다** |

**Elo에 시간 감쇠를 걸면 1900점짜리가 아무 이유 없이 1700점이 된다.**
온도계를 시간 지났다고 깎는 것과 같다.

### 5-6. ⭐ 대신 **은퇴(헌액)** — 점수를 깎지 말고 선수를 내보낸다

```
👑 7일 연속 TOP 3 유지  →  명예의 전당 헌액 + 현역 은퇴
   (또는 주간 결승 우승 → 즉시 헌액)

→ 매칭 풀에서 제외 (더 이상 대결에 안 나옴)
→ 상세 페이지·전당에서 계속 열람. 이어쓰기도 계속 가능
→ 🚨 왕좌 공석
```

**정보 이론적으로도 맞다.** 대결의 가치 = 불확실성 감소.
이미 챔피언이라고 확정된 상황을 계속 대결시켜봐야 **얻는 정보가 0**이다. 그 자리를 **예선 항목**에 줘야 한다.

**재미를 위한 처방과 데이터를 위한 처방이 정확히 일치한다.**

**그리고 은퇴가 콘텐츠가 된다:**
> 👑 **7일간 왕좌를 지킨 챔피언이 은퇴했습니다.**
> *"라면 물 다 맞췄는데 봉지에 수프가 없을 때"*
> **왕좌가 비었습니다. 다음 왕은 누구입니까?** → 전원 알림

### 5-7. 배치고사는 만들지 않는다 ❌

```
첫 5판 이진탐색 배치고사 → 오차 116 Elo
첫 5판 그냥 근접 매칭    → 오차 118 Elo    ← 차이 2점. 무의미
```

**투표 1건의 정보량이 너무 작다.** 5판으로는 어떻게 매칭해도 ±116점 이상 못 좁힌다.
복잡도만 늘고 이득이 없다. **그냥 30전 예선을 돌린다.**

### 5-8. 상태

| 상태 | 조건 |
|---|---|
| 🥚 예선 | 30전 미만 — 랭킹 미표시 (*"예선 12/30전"*, 오차 ±58 Elo까지 수렴) |
| ✅ 본선 | 30전 이상 |
| 💀 탈락 | 30전 후 하위 30% — **조용히 소멸** (알림 금지) |
| 🏛️ 헌액 | 7일 연속 TOP 3 — 은퇴 |

## 6. ✍️ 제보 — 규칙 기반 정규화 (AI 0원)

> **"AI가 할 일을 사람에게 떠넘기지 않는다. 규칙으로 없앤다."**

### 6-1. 즉시 게시 원칙 🚨

```
❌ 제보 → 검수 큐 → 운영자 정규화 → 게시    (지연 · 병목 · 성공하면 붕괴)
✅ 제보 → 규칙 검증 → 즉시 게시 → 사후 신고
```

```
사전 검수: 부하 ∝ 제보 수    → 성공하면 붕괴
사후 검수: 부하 ∝ 문제 건수  → 성공해도 감당된다
```

### 6-2. 입력 제약

| 제약 | 규칙 | 효과 |
|---|---|---|
| **길이** | 20~40자 하드 제한 + 카운터 | 벽글·단문 편차 제거 |
| **종결** | **"때"로 끝나야 제출 활성화** | **문체 통일의 80%** (존댓말·반말·음슴체 자동 소멸) |
| **예시 3개 상시 노출** | 화면에 항상 | **모방이 가장 강력한 정규화 장치** |
| **실시간 미리보기** | 대결 카드 모양 | 형식 이탈을 스스로 알아챔 |
| **"대충 쓰세요" 안내** | 크게 | 백지 공포의 정체는 "못 쓸까 봐" |

> 시스템이 어미를 억지로 붙이면 비문이 난다("아플 할 때"). **유저가 맞추게 한다.**

### 6-3. 자동 정제 (정규식)

```js
raw.replace(/\p{Extended_Pictographic}/gu, '')   // 이모지
   .replace(/[ㄱ-ㅎㅏ-ㅣ]+/g, '')                 // ㅋㅋ ㅠㅠ
   .replace(/(.)\1{2,}/g, '$1')                  // 아아아아 → 아아
   .replace(/[!?~^*_=+<>|\\/@#$%&]/g, '')
   .replace(/\s+/g, ' ').trim();
```

### 6-4. 반려 / 신고

| 사유 | 처리 |
|---|---|
| 욕설 · 광고·URL · 개인정보 패턴 | **자동 반려** (사전 + 정규식) |
| 혐오·정치·저격 · 축과 무관 | **사후 신고** → 3회 자동 숨김 |

### 6-5. 포기하는 것 (정직하게)
**문장 재구성은 안 한다.** *"샤워하고 나왔는데 배 아플 때"* vs *"샤워 개운하게 하고 나왔는데 바로 배가 아플 때"* — 이 정도 편차는 **감수한다.**
**완벽한 통일은 Phase 2(LLM)의 사치품이지, 없으면 안 돌아가는 필수품이 아니다.**

### 6-6. 10판 언락

| 기능 | 조건 |
|---|---|
| 투표 / 이유 한 줄 | **0판** (즉시) |
| **제보 / 이어쓰기** | **전역 1회 10판** ← 톤 학습 |
| 새 리그 | 3판 |
| **로그인 시** | 즉시 전부 해제 ← **로그인 유인** |

```
❌ "제보하려면 10판을 하세요"           ← 벌
✅ [■■■■■■■■■■] 🔓 제보 기능이 열렸습니다!  ← 선물
```

10판을 막 끝낸 **문맥이 가장 뜨거운 순간**에 제보 버튼이 열린다.

## 8. 💬 댓글 (= 커뮤니티의 씨앗)

### 8-1. 이유 (투표 직후)
> 💬 왜요? → *"배 아픈 건 참으면 되는데 지퍼는 못 되돌림"* 👍 342

**정규화하지 않는다.** 승패에 영향이 없으니 개성이 그대로 재미다.

### 8-2. 이어쓰기 + 승격 ⭐ 콘텐츠 공장
> 💬 *"근데 그게 남의 집일 때"* 👍 1,204 → **[🚀 승격]** → 독립 상황으로 참전

승격 시 **6장 규칙 검증**만 통과하면 **즉시** 등록.
**임계값: 그날 이어쓰기 중 상위 20%** (고정값 금지)

> **90-9-1 법칙**: 백지에 쓰기 **1%** / 남의 글에 얹기 **9%** → **콘텐츠 공급 9배**

### 8-3. 대댓글 없음 🚫
깊이 1. 전부 60자. **싸움이 붙으면 운영자는 게임 제작자가 아니라 분쟁 조정관이 된다.**

**영구히 남는 이름.** 뱃지는 흔해지지만 전당의 이름은 안 흔해진다.

## 12. 🚨 리그 확장 트리거 = **표 잉여** (소재 고갈 ❌)

```

리그 3개 = 표가 1/3로 분산 → 순위가 노이즈 → 아무도 안 믿음 → 죽음
```

```
✅ 확장 조건:
   일 투표 수 ÷ (문장 수 × 30) > 1.5 를  3주 연속 유지
```

| 3 | 리그 확장 | **표 잉여 확인 후에만** |

## 14. DB 스키마

```sql
arenas       (id, slug, name, emoji, is_open, supporter_count, created_at)

situations   (id, arena_id, display_text,
              first_reporter_id, report_count,
              elo, matches, wins,
              skip_count,              -- ★ 보편성 지표
              status,                  -- qualifying|active|eliminated|enshrined
              top3_streak_days,        -- ★ 헌액 판정 (7일 연속 TOP3)
              origin,                  -- seed|report|promoted
              embedding vector(768),   -- ☁️ Phase 2. P1: null
              created_at)

matches      (id, arena_id, sit_a, sit_b, winner_id,
              is_skip,                 -- ★ "안 겪어봤어요" → Elo 제외
              is_incumbent_a,          -- ★ 승자 잔류 (β 보정용)
              position_swapped,        -- ★ 좌우 랜덤 스왑
              voter_session, voter_id, weight,
              ms_elapsed, created_at)

elo_history  (situation_id, date, elo, delta_24h)   -- ★ 🔥오늘 탭 (ΔElo 정렬)

reports      (id, situation_id, raw_text, reporter_id, is_merge, merged_by, created_at)
reasons      (id, match_id, voter_id, text, upvotes, created_at)
replies      (id, situation_id, author_id, text, upvotes, promoted, created_at)
unlocks      (session_id, votes_count, unlocked_at)
titles       (user_id, title, situation_id, granted_at)   -- ★ 칭호
hall_of_fame (id, situation_id, hof_number, final_elo, inducted_at)
```

**인덱스**: `situations(arena_id, status, elo)` · `situations USING gin (display_text gin_trgm_ops)` · `elo_history(arena_id, date, delta_24h)`

### 🚨 지금 안 넣으면 데이터를 다시 모아야 하는 것

```
□ matches.is_incumbent      ← 없으면 β 추정 자체가 불가능
□ matches.position_swapped
□ matches.is_skip           ← 나중엔 "안 겪어본 사람의 투표"를 분리할 방법이 없다
□ 세션 내 (voter × situation) 판정 횟수
□ elo_history               ← 없으면 🔥오늘 탭을 못 만든다
□ reports.raw_text          ← Phase 2 프롬프트 학습 자산
```

**컬럼 몇 개, 코드 열 줄이다. 나중에 넣으면 그전 데이터가 전부 쓰레기가 된다.**

## 1. 최우선 — 공유 파이프 (P0)

두 갈래로 쪼갠다. 난이도·의존성이 달라서다.

### 1-A. 주제 OG 이미지 — 정적 사전 생성 (가장 싸고 확실, 먼저)

- **왜 이 방식:** 공개 주제는 34개로 **유한·결정적**. 런타임 생성(@vercel/og) 붙일 필요 없음. 이미 있는 `sharp` + 빌드 스크립트(`scripts/gen-images.mjs` 패턴)로 **주제별 1200×630 PNG를 미리 찍어** `static/og/<slug>.png`에 저장하면 끝. 신규 런타임 의존성 0.
- **구성:** 커버 이미지(첫 후보 webp) + 주제 제목 텍스트 + 브랜드 워터마크 → sharp `composite`로 1장 합성. webp→png 변환도 sharp가 처리(크롤러 호환 확보).
- **연결:** `t/[id]/+page.svelte:31` 아래에 `<meta property="og:image" content="{SITE}/og/{slug}.png">` + `twitter:image` 추가. 레이아웃의 default는 홈/사용자주제용으로 남김.
- **주의:** 레이아웃(L69)과 주제 페이지가 둘 다 og:image를 내면 중복. 주제 페이지가 값을 낼 땐 레이아웃 default가 안 나오게 정리(또는 크롤러가 마지막 태그를 읽도록 순서 보장).
- **비용:** 반나절. 라이브러리 추가 없음. → **여기부터 착수.**

### 1-B. 결과 공유 카드 — 클라이언트 이미지 저장 (인스타 스토리용)

- **왜 분리:** 사용자의 순위표는 **무한·개인화**라 사전 생성 불가. 주 용도는 "예쁜 내 티어표를 **이미지로 저장해서** 스토리에 올리기".
- **방식 결정 — html2canvas (클라이언트):**
  - 결과 블록(`play/+page.svelte:100-145`)을 예쁜 카드 레이아웃으로 만들고 → "이미지 저장/공유" 버튼에서 `html2canvas`로 DOM→PNG.
  - 크롤러 무관, **결과 영속화(URL/DB) 불필요** → 지금 구조에 바로 얹힘.
  - 카드 하단에 `codeinsight.online` **워터마크**(이미 PDF 푸터에 있는 문구 재사용) → 씨딩 시 출처 노출.
  - 가능하면 `navigator.share`(모바일 네이티브 공유 시트)도 함께.
- **디자인:** 1~3위 크게(🥇🥈🥉), 나머지는 S/A/B 티어. 세로 9:16(스토리 규격) 카드.
- **비용:** 1~2일(디자인 포함). `html2canvas` 1개만 추가.

### 왜 결과는 @vercel/og가 아닌가 (결정 근거)

"카톡에 **결과 링크**를 붙이면 그 사람 순위가 미리보기로 뜬다"는 건 매력적이지만, 그러려면 **① 결과를 URL/DB로 직렬화 + ② 런타임 OG 생성(@vercel/og)** 이 둘 다 필요하다. 현재 결과는 휘발성 클라 상태라 영속화 계층이 통째로 없다(주석상 "2단계 Supabase 예정"). → **이건 P1로 미룬다.** P0는 "이미지 저장 버튼"만으로 충분히 바이럴 시동이 걸린다.

## 3. 백로그 — "비교"의 재미 (P1~P2)

공유 파이프가 뚫린 뒤. 전부 **결과 영속화 + DB(Supabase, 주석상 예정)** 가 선행 조건.

1. **나 vs 전국 평균** — "당신의 취향은 상위 3%", "너구리 1위는 4%뿐". MBTI가 흥한 핵심(남과 비교). *선행: 결과 집계 저장.*
2. **커플/친구 대결 모드** — 링크 공유 → 각자 플레이 → "취향 일치율 73%". 공유가 **게임 시작 조건**이 되어 확산이 내장됨. *선행: 결과 저장 + 세션 매칭.*
3. **순위표 상성 분석** — "짜파게티 1위 → 포카칩 선호" 크로스 통계. 데이터 쌓이면 콘텐츠 자가생산. *선행: 대량 데이터.*

> 우선순위 논리: 1·2·3 모두 데이터가 있어야 성립. **P0(공유 카드)로 트래픽/데이터를 먼저 모은 뒤** 착수해야 순서가 맞다.

## 5. 학문적 심화 — 정확도·서사·정체성

> 목적: 같은 데이터에서 **더 정확한 순위 + 더 강한 서사 + 더 끈끈한 정체성**을 뽑아 공유 동력을 키운다.
> §3 백로그(나 vs 평균·대결·상성)의 구체 형태가 여기 5-6·5-3·5-7·5-8이다.

### ⚠️ 먼저: 현 엔진에 대한 사실 정정

현재는 "단일 토너먼트"가 **아니다.** `src/lib/ranking/mergeRanker.ts` = **인터랙티브 병합정렬**(n·log n, 16개 ≈ 32비교, `estimateComparisons`). 즉 **1위만 정확한 게 아니라 전체 순위가 이미 나온다.** 다만 두 구조적 약점:

1. **추이성 가정** (`mergeRanker.ts:40` 주석): `A>B, B>C ⇒ A>C`로 간주하고 **모순되는 쌍을 아예 안 물어봄** → 순환 취향(5-2)을 **구조적으로 탐지 불가.**
2. **점수·신뢰도 없음**: 결과가 등간격 순위뿐 → "상위 3%"·선호 강도·적응형 매치업(5-1)이 **계산 불가.**

이 두 병목 때문에 **5-1(Elo 전환)이 5-2·5-3·5-6·5-7·5-8의 전제**다. 엔진은 `RankSession<T>` 인터페이스(`ranking/types.ts`)로 추상화돼 있고 play 페이지가 그 인터페이스에만 의존하므로(`play/+page.svelte:21,44,50-58`), **엔진 교체는 국소적**이다.

### 수학

- **5-1. Elo / Bradley–Terry 전환.** 병합정렬 대신 매 선택을 승/패 로그로 쌓아 점수 갱신. 얻는 것: (a) 비교 횟수에 비례하는 **순위 신뢰도**, (b) **점수 → 상위%·강도**, (c) **적응형 매치업**(점수가 비슷해 예측 불가한 쌍을 우선 제시 = 정보이득 최대 = 사용자에겐 "계속 고민되는 매치업만 나온다"는 재미). 새 `RankSession` 구현 1개로 국소 교체. *DB 불필요(순위 품질 자체는 클라에서 됨), 집계 통계는 DB 선행.*
- **5-2. 비이행성(순환) 탐지 = "당신의 취향엔 가위바위보가 있다."** A>B>C>A 같은 모순을 오류로 버리지 말고 콘텐츠화: "취향 일관성 87점 — 3번의 모순 발견". **5-1 선행 필수**(현 엔진은 모순 쌍을 안 물음). 콩도르세 역설("전 국민 라면 순위는 수학적으로 완벽할 수 없다")은 집단 순위 스토리텔링 소재.
- **5-3. 취향 좌표계 / 임베딩 = "취향 쌍둥이 찾기."** 유저별 선택 벡터를 임베딩(간단: 순위 벡터 간 스피어만 상관, 정식: 행렬분해) → "취향 98% 일치 유저 존재", "취향 아웃라이어 상위 1%". *결과 저장 + DB 선행.*

### 심리

- **5-4. 제거 프레임(손실 회피).** "뭐가 좋아?" → **"하나가 영영 사라진다면 뭘 지키겠어?"** 손실의 고통(≈2배)이 진짜 선호를 끌어냄. "지옥의 제거전" 별도 모드 = 같은 데이터, 다른 체감. *엔진 재활용, DB 불필요.*
- **5-5. 망설임 시간 측정 = 암묵적 선호 강도. ★가성비 1위.** 원리: 반응시간 = 선호 강도의 역수(IAT). 구현: `play/+page.svelte`에서 새 쌍 표시 시각을 `refresh()`(L57 `pair = ranker.next()`)에 기록하고, `pick()`(L64-74) **진입 시각(L66, 900ms 애니 지연 전)** 과의 차를 저장. 결과 카드에 "가장 고뇌한 대결: 신라면 vs 진라면 (11.2초)" / "0.4초 컷". **타임스탬프 하나 추가 = 비용 거의 0, 서사성 급상승.** *DB 불필요, 결과 카드(§1-B)와 바로 결합.*
- **5-6. 예측 게임(허위 합의 효과).** 결과 보기 전 "전국 1위는 뭘 것 같아?" → 맞히면 "대중의 마음을 읽는 사람", 틀리면 "세상과의 거리 7칸". 착각이 깨지는 순간("어떻게 불닭이 1위임???")이 캡처·공유 순간. *집계 데이터 + DB 선행.*

### 사회학

- **5-7. 취향 부족(部族) — 구별짓기(부르디외).** 클러스터링(5-3 재활용)으로 유저를 군집화하고 이름 부여: "국물 원리주의자", "매운맛 급진파", "짜장 보수당". 순위표는 잊혀도 **이름표는 프로필에 걸린다**(MBTI가 흥한 원리). *5-3 + DB 선행.*
- **5-8. 지역·세대 대항전 — 갈등이 연료.** 데이터에 지역/연령 태깅: "국밥: 부산 vs 서울", "10대·40대가 유일하게 합의한 라면". 커뮤니티 떡밥의 **"공식 데이터 출처"**가 되면 링크가 자생. *결과 + 메타데이터 + DB 선행.*
- **5-9. 라이브 전국 월드컵 — 집단 열광(뒤르켐).** 매주 목 21시 전국 동시 플레이 + 실시간 집계 그래프. 혼자 = 심심풀이, 10만 명 동시 = 스포츠 관람. WebSocket 실시간 집계(사용자 본업 스택 재활용 가능). *실시간 인프라 + DB, 비용 대.*

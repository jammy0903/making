# 외부 자문 반영 · 로드맵 체크리스트 (2026-07-10)

> 게임 규칙/방식 발전을 위해 받은 외부 자문(심리·수학·사회학 관점)과, 그것을 우리 실제 코드에
> 대조해 도출한 반영 계획. 정본 스펙은 `docs/game-design.md`(A~F), 이 문서는 그 위의 개선안이다.

## 0. 자문이 우리 코드를 정확히 맞힌 부분 (검증됨)

`src/lib/game/engine.ts` · `src/routes/[[lang=locale]]/g/[deck]/+page.svelte` 대조 결과, 자문 지적이
실제 구현과 일치했다:

- **1판 정보가 버려진다** — `computeResult` 루프가 `i=1`(2판)부터 시작 → 1판 선택은 점수 미반영.
- **오실레이션(ABAB…) → 0:0 → 마지막 판 타이브레이크** — 매 판 갈아탄 유저를 "한쪽 선호"로 판정하는 건 부정확.
- **세로 스택 위치 편향** — `[deck.a, deck.b]` 고정 순서 → a가 늘 위(position bias ~10–15%).
- **조건 누적 전부 표시(접힘 없음)** — 7판 이후 인지 부하로 읽기 포기 위험.

## 1. 자문 핵심 요약

- **심리**: 현시선호(비용 지불 후에도 유지 = 진짜 선호) 설계는 옳음. 단 매몰비용/일관성 편향과
  겹치는데, 바이럴에선 오히려 확증편향과 맞물려 공유 욕구를 키우는 장점. 손실회피(페널티-온리)가 엔진.
- **초반 지루함은 필연·필요악**: 앵커링을 위해 초반 약한 조건이 있어야 후반이 세게 체감됨.
  문제는 "지루함"이 아니라 "무관심" → 초반을 **가볍지만 웃긴 이벤트형**으로. **3막 구조** 권장
  (1~3판 웃음용 가벼운 불편 / 4~7판 현실적 트레이드오프 / 8~10판 인생 결단).
- **강도 곡선은 엄격하되 유연**: 강도 N = "그 사이드 내 상대적 에스컬레이션 순서"로 정의(두 사이드 간
  절대 비교 불필요) → 유머와 에스컬레이션 체감 양립.
- **결과의 한 방 = 공유 심리**: 정체성/사회적비교/대화촉발. 현재 "버틴 깊이"는 정체성만 건드림.
  MBTI식 유형명 폐기는 옳으나 대체 훅 필요 → **문장형 라벨**("~해도 …못 버리는 사람") + **상위 N%**.
- **바이럴 루프**: "나→나(다른 주제)"는 약함. **결과카드→같은 주제 링크→결과 비교 페이지**가 핵심.
- **UGC는 퀄리티 절벽** → MVP엔 열지 말 것. 수제작 → LLM초안+큐레이션 → 승인제 UGC 순.
- **문서에 없던 지적**: 위치 편향 랜덤화 / 이전 조건 접힘 / 스위치 시 "아까움" 연출 / 데이터 윤리
  (선택 시퀀스+주제ID만 저장, 접속 메타데이터 미수집 — PIPA).

## 2. 반영 분류

### A. 지금 바로 (클라이언트만, 저비용·고효율) — 이번 배치
- [x] **A-1. 문장형 결과 라벨** — `「감수문구」 + ~좋아하는 타입` → `그래도 …못 버리는 사람` 완결 공유문장.
- [x] **A-2. 위·아래 위치 랜덤화** — 판마다 표시 순서 교체. **결과 로직엔 미사용(결정론 유지)**,
      고정 스크램블(5:5 균형)로 표시 순서만. 선택 기록은 여전히 사이드ID.
- [x] **A-3. 이전 조건 접힘** — 조건 3개↑면 "이미 N개 감수 중…" 요약 + 최신 조건만 강조.
- [x] **A-4. 오실레이션 별도 유형** — 스위치 4회↑ → `indecisive`("결정장애/둘 다 별로") 결과.
- [x] **A-5. 1판 가중치 1** — 1판 선택도 순수 취향 → 기본 점수 1.

### B. 구조 필요 (별도 착수 결정)
- [x] **B-1. 같은 주제 링크 → 결과 비교 페이지** (자문 2순위·바이럴 핵심). URL `?vs=<10선택>` 인코딩(서버리스).
      완주 시 공유 버튼(클립보드) → 받은 사람이 같은 덱 플레이 → 결과 카드에 "나 vs 상대" 비교. `engine.encodeChoices/decodeChoices`.
- [x] **B-2. 상위 N% 통계** — Supabase 연동 완료. `@supabase/supabase-js` + `src/lib/supabase.ts`(env 없으면 조용히 off).
      완주 시 `record_play` RPC(SECURITY DEFINER)로 익명 로그 기록 + 같은 덱·같은 선호편 중 버틴 깊이 상위% 반환.
      결과 카드에 배지 표시(표본 5개 미만이면 숨김). 마이그레이션 `supabase/migrations/0002_record_play.sql`.
- [x] **B-3. 스위치 시 "아까움" 연출** — 갈아타는 순간 "💔 {버린편} 두고 가는 거야…?" 토스트(1.3초 페이드).
- [ ] **B-4. 3막 구조로 덱 강도 재배치** — 콘텐츠 저작 가이드(1~3 웃음 / 4~7 트레이드오프 / 8~10 결단).
- [x] **B-5. 데이터 윤리** — (B-2에서 함께 충족) plays엔 덱ID·선택배열·랜덤 세션id·파생 캐시(선호편/깊이)만.
      접속 메타데이터(IP·핑거프린트) 미수집. plays는 RLS로 SELECT 불가 → 집계는 RPC 내부에서만.

### C. 보류/반대
- **UGC 즉시 오픈** — 자문도 반대. Phase 3로.
- **강도 로그스케일/S커브** — 자문도 "MVP엔 불필요". 선형 유지.

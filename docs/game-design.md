## A. 정밀 게임 규칙

### A-1. 한 판의 흐름

1. 화면에 두 사이드 (예: 🌞 여름 / ❄️ 겨울). 각자 지금까지 쌓인 `그런데 이제 …함. 근데 이제 …임.` 문장을 이고 있음.
2. **1판**: 둘 다 맨몸. 그냥 끌리는 쪽 선택 → 이게 "현재 내 편". (페널티 없음)
3. **2판부터**: 판 시작 시 **지금 내 편에 그 판 강도의 조건 한 장이 붙는다** — v3에선 조건 = **페널티+메리트 결합** (`그런데 이제 {페널티}. 근데 이제 {메리트}.`). 반대편은 그대로.

> **★v3 메커니즘 원칙 (엔트로피)**: 메리트가 붙어야 판마다 "그래도 이건 좋은데…" 저울질이 생겨 반대편 넘어갈 확률이 30~70%로 흔들린다(판별 엔트로피 0.7 bits/판 목표). 페널티-온리는 첫 판에 축이 굳으면 이후가 재확인 절차가 돼 재미가 0으로 수렴 → v3에서 폐기. 근거: [v3-pivot.md §1-2](./v3-pivot.md).
4. 선택:
   - **버팀(내 편 유지)** → 그 페널티를 "감수"로 기록.
   - **갈아탐(스위치)** → 방금 붙은 그 페널티가 나를 무너뜨린 것 = "싫어하는 것"으로 기록. 반대편이 새 내 편이 되고, 다음 판부터 걔에게 페널티가 붙기 시작.
5. 10판 반복 → 결과 카드.

> **내부/외부 구분**: "내 편"·페널티가 붙는 쪽·스위치 등은 *내부 규칙*일 뿐, **플레이 중 UI엔 라벨로 노출하지 않는다**(B-2). 모든 분석은 마지막 결과 카드에서 한 번에 공개.

### A-2. 강도 = 판 번호 (결정론, 랜덤 없음)

- 페널티 덱은 강도 1~10으로 태깅. **N판엔 무조건 강도-N 카드.** 내가 어느 편이든, N판에 붙는 건 *그 편 덱의 N번 카드*.
- → 문장이 판마다 반드시 세지고, 왔다갔다해도 난이도를 못 피함(오실레이션 악용 방지).
- MVP는 이 결정론으로 충분 — 주제당 페널티 덱 딱 10장, 순서 고정. **랜덤·티어당 다중 카드는 나중.**

### A-3. 강도 곡선 (가이드라인 — 엄격 고정 아님)

3막을 **성향**으로만 따르고, 칼같이 지키지 않는다 (지키면 형식화되어 재미 죽음):

- **1판**: 워밍업 (맨몸, 순수 취향)
- **2~4판**: 라이트 — 생활 불편 (에어컨·지하철·폭염) 😅
- **5~7판**: 시리어스 — 돈·커리어 (월급 삭감·계약 조건) 😰
- **8~10판**: 킬러 — 관계·정체성·영구 (애인·평생) 💥

원칙: *전반적 강도 상승은 유지*하되, 예측을 깨는 **커브볼 1~2장 허용** (초반에 묵직한 한 방, 후반에 실없는 한 장). 후반으로 갈수록 스위치(임계점)가 터지도록 배치.

### A-4. 스위치 처리 (페널티-온리)

- 페널티는 항상 **현재 내 편에만** 붙는다. 반대쪽은 안 건드림.
- 스위치해도 게임 계속. **쌓인 페널티는 리셋 안 됨** — 떠난 편의 페널티는 그대로 남고, 새 편에 새로 누적(양쪽 다 누적).
- 스위치 순간 = 손절 임계점. `(판·강도·카드)` 별도 기록 → 결과 카드의 "싫어하는 것".
- ⚠️ **"임계점"은 내부 용어.** 사용자 UI엔 절대 노출하지 않음(B-2).

### A-5. 결과 계산 알고리즘 (전부 로그에서, 무-AI)

> **v3 위치**: 아래 계산(선호편·버틴깊이·오실레이션)은 **표면 문구가 아니라, 어느 캐릭터 카드(극단/애매)를 띄울지 고르는 내부 신호**로 쓴다. 표면 결과는 §D-2 캐릭터 카드. (버틴깊이 완주강도 → 극단/애매 분기, 선호편 → 어느 편 카드.)

플레이 로그 = `[(판 N, 고른 편, 그 판 붙은 카드, 강도 N)]` (1판은 카드·강도 없음).

**선호 편 판정 = 비용가중 감수 강도 (revealed preference)**
- 각 판에서 "버팀"(직전 편 유지)이면 → 그 편에 `+강도N` 점.
- 편별 점수 = Σ(그 편을 지킨 판들의 강도).
- **점수 높은 편 = 선호 편.** 동점이면 마지막(10판) 선택으로 타이브레이크.
- 근거: 단순 다수결(n=10)·마지막 한 판(n=1)보다, "얼마나 큰 비용을 감수하고 지켰나"가 현시선호에 가장 부합. 게임 핵심 신호(강도)를 그대로 사용.

**결과 표현 = "버틴 깊이 대조"** (카드 한 장 비난 금지)

⚠️ 교체 이유: "싫어하는 것 = 스위치 유발 카드"로 쓰면, 일찍 손절한 사람은 트리비얼한 카드(강도3 지하철)가 튀어나와 "사소한 것 때문에 평생 포기"처럼 **앞뒤가 안 맞음**. 선호 판정은 멀쩡하나 *번역*이 틀린 것 → 양쪽 버틴 깊이 대조로 바꿈.

- `완주 강도`(편별) = 그 편을 지키며 버틴 **최고 강도**. (안 버틴 편 = 0)
- 결과 카드 요소:
  1. **감수 하이라이트** = 선호 편에서 버틴 센 카드들 → "~해도 [선호편]을 좋아하는 타입".
  2. **버틴 깊이 대조** = "[선호편]은 강도X까지, [버린편]은 강도Y에서 손절 → [선호편] 위해 (X−Y)단계 더 버팀".
  3. **손절 시점별 말투** (코히런스 확보):
     - 버린편 완주 강도 낮음 → "[버린편]엔 애초에 정이 없었네".
     - 버린편 완주 강도 높음(많이 버티다 무너짐) → "[버린편]도 여기까진 갔지만 ○○가 마지막 지푸라기".
     - 스위치 0회 → "아무것도 못 흔든 [선호편] 근본".

## B. 화면·UX 흐름

### B-1. 플랫폼 · 레이아웃
- 모바일 우선, 세로. (1분 플레이 · 폰에서 공유)
- 두 사이드를 **세로 스택** (위치 고정: 여름 위 / 겨울 아래). 가로는 긴 한글이 끼여서 배제.
- 각 패널 = 누적된 `그런데 이제 ~해도` 문장 + 그 자체가 선택 버튼(탭).

### B-2. 플레이 중엔 메커니즘 전부 숨김 ★

플레이 화면은 **아무 분석도 노출하지 않는다.** 끝에 결과 카드로 한 번에 "짠" 공개하는 게 핵심 재미.

- ❌ "현재 내 편" 라벨·하이라이트 없음.
- ❌ 점수·스위치 횟수·선호 판정 같은 계산 과정 없음.
- ❌ "임계점" 등 내부 용어 절대 노출 안 함. 스위치해도 조용히 진행("너 갈아탔어" 식 지적 없음).
- ✅ 유저는 매 판 두 선택지를 보고 하나 탭할 뿐. 조건이 쌓이는 건 문장으로 자연히 느껴짐(라벨 없이).

### B-3. 한 판 인터랙션
- 이어온 선택지엔 그 판 조건이 하나 더 붙어 문장이 길어진다 ("이렇게까지 돼도?" — 말로 설명 안 하고 문장으로만).
- **누적 연출 = 과한 연출** (카드가 날아와 쿵 쌓이는 식). → **후보, 확정 아님.**
- 탭 = 그 편 선택. 별도 버튼 없음(패널이 버튼).

### B-4. 진입 = 주제 선택 (PIKU식) ★
- "오늘의 주제" 폐기. **여러 주제 그리드**에서 골라서 시작.
- 예: 여름vs겨울 · 개vs고양이 · 아침형vs저녁형 · 부먹vs찍먹 …
- 흐름: 주제 그리드(홈) → 10판 → 결과 카드 → (공유 / 홈으로 돌아가 다른 주제).

### B-5. 화면 목록
1. **홈** — 주제 선택 그리드
2. **플레이** — 10판 (메커니즘 숨김)
3. **결과 카드** — 짠, 전체 분석 공개 (D에서 상술)

## C. 콘텐츠(덱) 설계

### C-1. 주제 = 덱 1개의 구조
페널티-온리라 **한 주제에 페널티 덱 2개** (사이드마다):
```
주제: {제목} {아이콘}
├ 사이드 A → 페널티 10장 [강도 1~10]
└ 사이드 B → 페널티 10장 [강도 1~10]
```
- 각 덱 = "이 편을 버리고 싶어지는 이유"가 강도순 10장.
- 두 덱은 **독립 저작**이되, 같은 강도 티어끼리 무게를 맞춤 → 어느 경로로 가도 에스컬레이션 체감이 일정.

### C-2. 카드 문구 규칙 (v3 · 페널티+메리트 결합)
- **렌더 틀**: `그런데 이제 {페널티}. 근데 이제 {메리트}.` — 모든 조건이 **페널티+메리트 결합(필수)**. 페널티 단독 폐기.
- **말투 = 음슴체** (`~함 / ~임 / ~됨`, 감수·의무형은 `~해야 함`). **양보형(~해도)은 안 씀** (구 규칙 폐기).
- **메리트 4원칙**: ①같은 도메인 인과 연결 ②페널티 감정 강도 ≥ 메리트 × 2 ③컨셉 배신 금지 ④3초 저울질 발생. (상세·예시: [v3-pivot.md §2-1](./v3-pivot.md), [deck-authoring-guide.md](./deck-authoring-guide.md).)
- 강도 곡선(A-3)은 소프트 가이드 — 커브볼 허용.

### C-3. 카드 스타일 = 조건형 vs 이벤트형 (★이벤트형 선호)
- **조건형**: 추상 상태 ("에어컨 없어도", "월급 30% 삭감이어도"). 여름vs겨울에 적합.
- **이벤트형**: 구체적 사건·에피소드 ("분위기 잡다 매번 배 아프다며 뛰쳐나가도"). 훨씬 웃기고 바이럴 강함 → **가능하면 이벤트형 선호.**
- 둘 다 "~해도"로 끝나 형식은 동일.

### C-4. 저작 포맷 (손저작 MVP)
주제당 구조화 데이터 1개. (유저 크리에이터·LLM 생성은 나중.)
```
{ id, 제목, 아이콘,
  sideA: { name, emoji, penalties:[{강도, text}, ...10] },
  sideB: { ... } }
```
→ 지금은 초안이 문서에 흩어져 있으나(§C-5 · balance-game-plan §4), 구현 시 주제별 데이터 파일로 통합.

### C-5. MVP 주제 = 2개 (손저작)

**주제 1 · 여름 🌞 vs 겨울 ❄️** (조건형)
덱: [balance-game-plan §4.1(여름 페널티)·§4.2(겨울 페널티)](./balance-game-plan.md).

**주제 2 · 결혼한다면? 얼굴천재 🤩 vs 개그천재 😆** (이벤트형)
> 실명 대신 **아키타입** — 차은우급/유병재급이 자연히 연상되되 실명 아님(명예훼손·§0 연예인 리스크 회피). 카드는 PIKU 스타일로 오리지널 창작(문구 표절 회피).

얼굴천재 페널티 [강도 1~10]:
1. 얼굴 빼면 대화 3분컷이어도
2. 데이트마다 본인 셀카 200장 찍느라 넌 뒷전이어도
3. 거울 앞을 못 지나쳐 매번 1시간 늦어도
4. 코골이+이갈이 풀세트여도
5. 화장실 문 안 닫고 큰일 보며 말 걸어도
6. 분위기 잡다 갑자기 배 아프다며 매번 뛰쳐나가도
7. 월급 전부 피부과·옷에 쓰고 생활비는 네가 다 내도
8. 전 애인 20명이 아직 연락 오고 답장도 해도
9. 시어머니가 열쇠 들고 예고 없이 들이닥쳐도
10. 평생 잘생겼지만 평생 철은 안 들어도

개그천재 페널티 [강도 1~10]:
1. 첫인상이 좀 많이 그래도
2. 같이 찍은 사진마다 너만 잘 나와도
3. 친구들이 "왜 하필 쟤?" 매번 물어봐도
4. 진지한 얘기마다 5초에 한 번 드립쳐도
5. 프러포즈도 개그로 해서 감동 0이어도
6. 중요한 순간마다 방귀로 분위기 깨도
7. 집에선 안 웃기고 밖에서만 인싸여도
8. 예능 스케줄로 신혼집 자주 비워도
9. 장모님 앞에서까지 드립치다 미움받아도
10. 평생 안 잘생겼어도

## D. 결과·공유

### D-1. "짠" 공개 연출
10판 끝 → 짧은 서스펜스 → 결과 카드 등장. 플레이 중 숨긴 분석(B-2)이 여기서 한 번에 터짐.

### D-2. 결과 카드 = 캐릭터 카드 (v3 · 세로 9:16, 스토리·카톡 공유 규격)

⚠️ **v3 전환**: 숫자 카운트·"버틴 깊이 대조"를 **표면에서 폐기**. 결과 = **공유 가능한 캐릭터 카드 3스텝**(커뮤체·킹받게).
(버틴깊이·선호편·오실레이션은 계속 계산하되, **어느 캐릭터 카드를 띄울지 고르는 내부 신호**로만 씀 — §A-5.)

**캐릭터 카드 3스텝** = `ResultCard { taunt, stats[], curse }` (상세·예시: [v3-pivot.md §2-2](./v3-pivot.md))
1. **놀림 헤드라인(taunt)** — `ㅋㅎㅋ 당신은 ~쟁이누/~덕후였네/~먹보잖아?` 반말·디시/에펨 하드 놀림. 가장 크고 강한 줄. (구 명사구 유형명 폐기 — 얌전해서 안 킹받음.)
2. **이유=특이 스탯(stats) 3~5개** — `▸ {측정 대상}: {구체 숫자}` (예 `▸ 인생 총 셀카: 1,204,000장`). 실제 버틴 조건과 연결, 측정 불가·이미 아는 정보 금지.
3. **예언/저주(curse) 문장만** — 접두 라벨("예언:"·"예상 X:") 없이 **문장 하나.** 사주 밈 톤·확정. **캡처했을 때 가장 강한 한 줄.**

```
━━━━━━━━━━━━━━━━━━━━━━━━━
ㅋㅎㅋ 당신은 {놀림 헤드라인}
━━━━━━━━━━━━━━━━━━━━━━━━━
▸ {특이 스탯 1~3}
━━━━━━━━━━━━━━━━━━━━━━━━━
{예언/저주 문장 한 줄}
━━━━━━━━━━━━━━━━━━━━━━━━━
동일 유형 비율: 상위 {N}%   ·   그런데 이제  #주제
```

**카드 분기 = 편당 2종** (덱당 총 4종): **극단**(강도 8+까지 우세 → 캡처 유발) / **애매**(강도 5~7 전환 → "이 유형인 줄 몰랐네" 발견감). 내부 신호(버틴깊이 §A-5)로 극단/애매를 판정해 해당 편의 카드를 띄움.

### D-3. 이미지화
결과를 **PNG로 렌더 → 저장·공유.** 텍스트보다 이미지 카드가 인스타 스토리·카톡 바이럴에 유리.

### D-4. 공유 URL = 바이럴 루프
- 링크엔 **결과 요약만** 인코딩(선호편·완주 강도·감수 하이라이트). 플레이 로그 전체는 무거워서 제외.
- 링크 열면: **내 결과 카드 미리보기 + "나도 해보기" CTA** → 같은 주제로 즉시 유입.

### D-5. 3층 통계 (MVP 끔)
"같은 편 상위 N%"는 데이터 쌓인 뒤 슬며시 오픈(콜드스타트 회피, §2). MVP엔 표시 안 함.

## E. 데이터 모델 (논리 스키마 — 기술 무관)

로그인 없음 · 익명 전제(개인정보 안 받음). 데이터는 3덩이.

### E-1. 덱 (콘텐츠)
```
deck {
  id, 제목, 아이콘,
  sideA: { name, emoji },  sideB: { name, emoji },
  penaltiesA: [{강도 1..10, text}]×10,
  penaltiesB: [{강도 1..10, text}]×10
}
```
- **저장 = DB 소스 오브 트루스 + git 시드.** 런타임은 DB에서 읽고, 공식 2덱은 **git 시드/마이그레이션 파일**로 버전관리(PR 리뷰·롤백). → UGC·어드민·통계로 재작업 없이 확장.
- 근거: UGC 로드맵은 DB 필수 + 플레이 로그 DB가 이미 day1부터 존재 → 콘텐츠 DB 한계비용 ≈ 0.

### E-2. 플레이 로그 (append-only)
```
play {
  id, deck_id, 익명세션id, created_at,
  choices: [사이드]×10,      // 원본 — 결과 계산 전부 여기서(§A-5)
  반응시간: [ms]×10,          // 옵션
  // 파생 캐시: 선호편, 완주강도A, 완주강도B
}
```
- 원본은 `choices` 하나면 충분. **출시부터 익명 로그 축적**(3층 대비, §2 콜드스타트), 표시는 나중.

### E-3. 집계 (3층 · 나중)
`play`를 deck_id로 묶어 선호편·완주강도 분포 → "상위 N%". MVP엔 안 켬(D-5).

### E-4. 공유는 무서버
공유 URL(D-4)은 결과 요약을 URL에 인코딩 → 링크 열기엔 DB 조회 불필요.

## F. MVP 범위 / 안 할 것

**스택**: SvelteKit + Supabase (무서버 공유 + DB 로그에 적합, 러닝커브 낮음). **언어**: 한국어 온리 (밈·말맛이 한국어 의존적, i18n은 나중).

**✅ MVP에 넣는 것**
- 주제 선택 홈 (2주제: 여름겨울 · 결혼)
- 10판 플레이 — **페널티+메리트 결합 조건**(v3), 메커니즘 숨김(B-2), 과한 연출(후보)
- 결과 카드 — **캐릭터 카드**(유형네이밍+특이스탯+미래예언, §D-2) + PNG 이미지화
- 공유 URL — 결과 미리보기 + "나도 하기" CTA
- 익명 플레이 로그 저장 (표시 안 함, 3층 대비 축적)
- DB — 덱 소스(git 시드) + 플레이 로그

**⛔ 빼는 것 (나중)**
- 3층 통계(상위 N%) — 데이터 쌓인 뒤
- 유저 크리에이터(UGC) · 어드민 편집 화면
- 카드 랜덤 / 티어당 다중 카드 (MVP는 주제당 10장 고정)
- 로그인·계정
- 다국어(i18n)
- 반응시간 활용 · 강도곡선 A/B

**성공 기준**: "공유 → 유입 → 또 공유" 루프가 도는지. 지표 = 플레이당 공유율 · 공유링크 유입 전환율.

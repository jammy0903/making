# 짤 대량 수집 계획 (Pinterest 2차 크롤)

현재 860개. 목표는 "핀터레스트에 있는 웃긴 짤을 사실상 다 가져온다"에 가까운 수준.
이 문서는 그게 어디까지 가능하고, 어디가 진짜 병목인지를 실측 기준으로 적는다.

관련: [jjal-archive-plan.md](./jjal-archive-plan.md) (스키마·검색·재호스팅 금지 원칙은 그쪽이 기준)

## 0. 결론 먼저

- **수집은 병목이 아니다.** 아래 방법으로 수만 장은 무리 없이 모을 수 있다.
- **병목은 "웃긴 짤만 남기기" 판정이다.** 860개를 거를 때 서브에이전트 18개가 필요했다.
  5만 개를 같은 방식으로 보면 비용이 60배가 된다.
- 따라서 계획의 절반은 수집이고, 나머지 절반은 **싸게 거르는 깔때기**다.

## 1. 실측 (2026-07-21)

기존 크롤러(`scripts/crawl_jjal_pinterest.py`)는 headless chromium `--dump-dom` 단일 스냅샷이라
키워드당 약 87개에서 멈춘다. 원인 두 가지를 확인했다.

| 확인한 것 | 결과 |
| --- | --- |
| `mouse.wheel(0, N)` | **동작 안 함.** scrollY가 0에서 안 움직임 (로그인 게이트 `[role=dialog]` 2개가 이벤트를 먹음) |
| `evaluate('scrollBy(0,4000)')` | 정상 스크롤. scrollHeight가 6.9k → 29.5k로 계속 자람 |
| DOM 가상화 | 지나간 핀은 DOM에서 제거됨 → **스크롤할 때마다 증분 수집해야 함** |
| 키워드 1개 / 30스크롤 | **387개** 수집 (기존 87개의 4.4배), 증가율 선형, 상한 안 만남 |
| 비로그인 상태 | 게이트 배너는 뜨지만 스크롤·수집은 계속 가능 |

→ 수집량 ≈ `키워드 수 × 스크롤 깊이`. 둘 다 우리가 조절하는 값이다.

## 2. 수집 규모를 늘리는 네 갈래

핀터레스트에는 "전체 목록"이 없다. 완전 열거는 불가능하고, 서로 다른 진입점으로
**커버리지를 겹쳐 쌓는 것**이 현실적인 최선이다.

### ① 스크롤 깊이 (세로)
키워드당 30 → 100스크롤. 실측 기울기(약 13개/스크롤)로 키워드당 **1,000~1,300개** 기대.

### ② 키워드 확장 (가로)
한국어 + 영어권 밈 포함. 축을 나눠서 짠다.
- 커뮤니티 밈 용어: 짤방, 드립, 병맛, 인정, 킹받네, 어쩔티비 …
- 구체적 상황·감정: 퇴근, 월요일, 현타, 억울, 민망, 눈치, 야근, 시험 망함 …
- 예능/방송 캡처: 무한도전 짤, 박명수 짤, 런닝맨 짤, 나는 SOLO 짤 …
- 인물·캐릭터: 릴러말즈, 무덕이, 퀸, 잔망루피, 최준 …
- 동물 리액션: 고양이 리액션, 강아지 억울, 햄스터 짤 …
- 영어권: funny meme, reaction meme, cat meme, relatable meme, cursed image,
  wojak, distorted meme, funny animal reaction …

150~250개 키워드 × 1,000 ≈ **15만~25만 후보**(중복 포함).

### ③ 연관 핀 그래프 (깊이)
①②로 건진 **좋은 핀**의 `/pin/{id}/` 상세 페이지에는 "More like this"가 붙는다.
좋은 핀 1개 → 연관 20~40개. 이미 웃기다고 판정된 핀에서만 뻗으므로 **적중률이 검색보다 훨씬 높다.**
키워드 검색이 못 닿는 롱테일을 여기로 흡수한다. 2~3홉까지만.

### ④ 보드 크롤
"웃긴 짤 모음" 류 보드 하나에 수백~수천 핀이 들어 있다. 사람이 이미 큐레이션한 묶음이라
노이즈가 낮다. 좋은 핀의 소속 보드를 타고 들어간다.

> 순서는 ① → ② → (판정) → ③ → ④.
> ③④는 판정 결과를 입력으로 쓰기 때문에 반드시 한 번 걸러진 뒤에 돈다.

## 3. 진짜 병목: 판정 깔때기

수집물을 그대로 넣으면 안 된다. 아래로 단계마다 후보를 줄여서 **비싼 판정에 도달하는 수를 최소화**한다.

| 단계 | 방법 | 비용 | 통과 예상 |
| --- | --- | --- | --- |
| A. URL 중복 제거 | pinimg 경로 해시 (기존 방식) | 0 | 25만 → 10만 |
| B. 이미지 중복 제거 | 썸네일 dHash, 해밍거리 ≤ 5 | 매우 쌈 | 10만 → 6만 |
| C. 형태 필터 | 비율 극단(배너·긴 인포그래픽), 해상도 미달, GIF 여부 | 0 | 6만 → 4만 |
| D. 텍스트 프리필터 | `alt` 텍스트 + 키워드로 명백한 비대상 제거 (패션·인테리어·아이돌 화보 등) | 0 | 4만 → 2만 |
| E. 임베딩 근접 필터 | 이미 KEEP된 860개의 캡션 임베딩 중심에서 먼 후보 컷 | 쌈 | 2만 → 8천 |
| F. 비전 판정 | 서브에이전트가 썸네일 보고 KEEP/DELETE + 한국어 캡션 + 키워드 | **비쌈** | 8천 → 4~5천 |

F가 전체 비용을 지배하므로 **A~E를 얼마나 독하게 조이느냐가 계획의 성패**다.
F의 산출물인 한국어 캡션은 검색 품질의 8할이라, 여기서만큼은 대충 하지 않는다(설계서 원칙).

E의 컷 기준은 감으로 정하지 않는다. 검색 거리컷(`DIST_MAX = 0.19`)을 정할 때처럼
**샘플을 실측해서 정한다.**

## 4. 단계별 실행

### Phase A — 크롤러 교체 (선행 필수)
`scripts/crawl_jjal_pinterest.py`를 Playwright 기반으로 다시 쓴다. 바뀌는 점:
- `--dump-dom` 스냅샷 → 브라우저 세션 유지 + `evaluate('scrollBy')` 루프
- 스크롤마다 `img[srcset]` 증분 수집(가상화 대응)
- 새 항목이 N회 연속 0이면 조기 종료
- 키워드별 진행 상황을 JSON에 **중간 저장**(중단해도 이어서 가능)
- 이미지는 여전히 **내려받지 않는다** — 재호스팅 금지 원칙 유지, pinimg 직링크만

### Phase B — 소규모 검증 (10키워드)
10개 키워드 × 100스크롤을 돌려 실제 수확량과 A~E 통과율을 잰다.
여기서 나온 숫자로 전체 규모와 F 비용을 다시 계산한다. **B 없이 전량 크롤 금지.**

### Phase C — 본 크롤
검증된 키워드 세트 전량. 예의상 간격 유지, 밤 시간대 분할 실행.

### Phase D — 깔때기 A~E 구현 후 F 판정
판정은 배치로 쪼개서 중간 결과를 계속 적재(한 번에 몰아 돌리다 날리지 않게).

### Phase E — 적재 + 임베딩
기존 파이프라인 그대로: 벌크 upsert → `scripts/embed_jjals.py` → 배포.
행이 수만 개가 되면 그때 **ivfflat 인덱스를 만든다**(설계서: 수만 행 전까지는 만들지 않음).

## 5. 리스크

| 리스크 | 대응 |
| --- | --- |
| 대량 요청 차단 | 간격 유지, 동시성 낮게, 조기 종료로 불필요한 요청 제거 |
| 죽은 링크(pinimg 만료) | 설계서의 dead-link 점검 배치를 이 시점에 같이 구현 |
| 저작권 | 재호스팅 금지 원칙 유지 — 직링크 + `source_url` 출처 보존 |
| F 비용 폭주 | Phase B 실측 전에는 본 크롤도 판정도 시작하지 않는다 |
| 품질 희석 | 수가 늘수록 "웃긴 것만"이 흐려짐. KEEP 기준은 1차 때 정한 것 그대로 유지 |

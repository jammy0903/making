# 검색 수요 기반 밈 발굴 — 설계서

> 발굴 1순위 엔진의 설계 문서. 실행 체크리스트는 [discovery-plan.md](./discovery-plan.md),
> 전체 발굴 철학·문헌은 [discovery-design.md](./discovery-design.md) 참조.
> 조사·엔드포인트 실검증: 2026-07-16 (이 문서의 URL은 그 날짜 기준 200 확인).

## 0. 배경 — 왜 검색 수요인가

- 경험적 사실: 지금까지 등록된 밈 중 **자동 n-gram(댓글) 파이프라인이 찾아준 것은 0개**.
  밈은 영상·짤·클립에서 태어나고 댓글은 메아리라, 댓글 통계는 후행·노이즈·시각밈 누락.
- 반면 **"○○ 뜻" 검색**은 밈 확산의 직접 증거다. 사람이 밈을 접하고 뜻을 모르면 검색한다.
  이 수요는 우리 SEO 착지 페이지("○○ 뜻 — memedics")와 동일한 수요 = 발굴과 유통이 한 신호를 공유.
- 문헌: 검색량 기반 감지(nowcasting, Choi & Varian 계열)는 확립된 방법론.
  Zhang 2016(JCMC): 인터넷 슬랭은 니치 커뮤니티→대중 확산. → **니치에서 발견, 대중(검색량)으로 검증**.

## 1. 목표 / 비목표

- **목표**: 미등록 밈/신조어 후보를 주 0~10개 규모로 관리자 큐에 올린다. 정밀도 우선(승인율 ≥50% 목표).
- **비목표**: 실시간성(일 1회면 충분), 완전 자동 등록(결정은 항상 사람), 검색량 절대치 추정.

## 2. 아키텍처

```
        ┌──────────── 후보 공급 (여러 채널 합집합) ────────────┐
        │ A. 구글트렌드 RSS   B. 검색광고 연관키워드            │
        │ C. 정리글 스카우트   D. /submit 신청   E. (보조) n-gram │
        └───────────────┬───────────────────────────────┘
                        ▼
              dedup: 등록밈 키워드 · rejected_terms 제외
                        ▼
        ┌──────────── 검증 (데이터랩) ────────────┐
        │ X와 "X 뜻"을 같은 호출에 조회            │
        │ + (가점) 자동완성에 "X 뜻" 존재          │
        └───────────────┬─────────────────────┘
                        ▼
              LLM 4-way 분류 {밈/신조어·고유명사·일반어·오타}   ← Phase 2와 공용
                        ▼
              discovery_candidates(kind='term', pending)
                        ▼
              관리자 큐(/manage-8949) — 등록/반려(반려→rejected_terms 환류)
```

## 3. 채널 상세

### A. 구글 트렌드 실시간 RSS — ✅ 검증됨, 키 불필요
- `GET https://trends.google.com/trending/rss?geo=KR` (2026-07-16 HTTP 200, XML)
- 내용: 한국 급상승 검색어 ~20개/일, `<title>` = 검색어, `ht:approx_traffic` = 대략 트래픽.
- 특성: 뉴스·사건·인물이 대부분 → **"X 뜻" 검증이 필수 필터**. 밈은 가끔 섞여 나오지만 그때가 귀중.
- 수집: 일 1회(크론)에 파싱해 후보 풀에 넣는다. XML 파싱은 정규식 수준으로 충분(제목만 필요).
- 실패 모드: 포맷 변경/폐지 가능성 → 파싱 실패 시 경고 로그만 내고 파이프라인 계속(격리).

### B. 네이버 검색광고 keywordstool — 가입 필요(무료), 절대 검색량
- `GET https://api.searchad.naver.com/keywordstool?hintKeywords=<시드>&showDetail=1`
- 인증: `X-API-KEY`, `X-Customer`, `X-Signature`(HMAC-SHA256, timestamp+method+path). 광고주센터 → 도구 → API 사용 관리에서 발급.
- 반환: `relKeyword`(연관키워드) + `monthlyPcQcCnt`/`monthlyMobileQcCnt`(**절대 월간 검색수**) — 데이터랩 상대값 약점 보완.
- 시드 전략: `밈`, `신조어`, `유행어`, `짤`, `밈 모음`, + 등록밈 상위 몇 개(연관에 이웃 밈이 뜬다).
- 용도 둘: ①연관키워드 = 후보 공급 ②절대 검색량 = 후보의 규모 감(월 1천 미만이면 보류 등).
- 상태: **키 발급 전** — 발급되면 활성화. 그전까진 A+C+D로 충분히 굴러감.

### C·D·E. 기존 채널
- C 정리글 스카우트(`src/naver/scout.js`): "요즘 밈 정리" 글 낚기 — 제목에서 후보 어휘 추출 강화 여지.
- D `/submit` 회원 신청: 이미 작동. 후보 풀에 합류.
- E n-gram 버스트(Phase 0 누적): 신조어 조기감지 보조. 누적 14일 후 gate 열리면 합류.

### 자동완성 (가점 신호, 비공식)
- `GET https://ac.search.naver.com/nx/ac?q=<X 뜻>&st=100&r_format=json` (비공식 — 차단 감수, 실패해도 무시)
- "X 뜻"이 자동완성에 뜸 = 그 뜻을 검색하는 사람이 실존 → 강한 가점.

## 4. 데이터랩 검증 상세 (`src/naver/datalab.js`)

- `POST https://openapi.naver.com/v1/datalab/search` (기존 `naver/client.js` 재사용, 일 1,000회 한도)
- 요청: `keywordGroups` 최대 5그룹/호출, 그룹당 keywords 최대 20개. `timeUnit: 'date'`, 기간 최근 60일.
- **상대값 함정과 앵커 정규화**: ratio는 요청 내 최대치=100인 상대값이라 호출 간 비교 불가.
  → 매 호출에 **앵커 그룹**(검색량이 안정적인 기준 키워드, 예: "날씨")을 1그룹 고정으로 넣고
  후보 ratio를 앵커 대비 비율로 환산하면 호출 간 비교 가능해진다.
- 호출 구성: 5그룹 = 앵커(1) + 후보 X(1) + "X 뜻"(1) + 다음 후보(2) → **호출당 후보 2개**. 일 1,000회 = 후보 2,000개/일로 충분.
- **판정 규칙 (초안 — 드라이런으로 튜닝)**:
  - `X 뜻` ratio가 최근 14일 내 0→양수 전환, **또는** 직전 4주 평균 대비 최근 7일 ≥3배
  - AND `X` 자체도 상승 추세 (뜻만 튀는 건 드묾 — 노이즈 방지)
  - 가점: 자동완성 "X 뜻" 존재 / 검색광고 월간검색수 존재
  - 제외: 등록밈 키워드와 부분문자열 겹침, rejected_terms
- 뉴스 필터: 뉴스·인물·사건은 "X 뜻" 검색이 거의 없다 → "X 뜻" 조건 자체가 필터.

## 5. 저장·큐 연결

- `discovery_candidates` 확장(Phase 2 스키마 선행 적용): `kind('url'|'term')`, `term`, `evidence(jsonb)`, `score`.
  - evidence 예: `{ "gtrends": true, "datalab": {"x": [..7d], "x_ttut": [..7d]}, "autocomplete": true, "monthly_qc": 12400 }`
- 기존 url형 후보(스카우트)와 공존. 관리자 후보검토 탭에서 term형 렌더(뜻 후보·근거·점수) — Phase 2 항목과 동일.
- 반려 → `rejected_terms` 기록(이미 존재) → 공급단 dedup에 즉시 반영.

## 6. 스케줄·통합

- GH Actions 일일 크론(crawl.yml)에 이어 붙임: 크롤 → (신규) `discover-search` 단계.
- 순서: RSS 수집 → dedup → 데이터랩 검증(신규 후보만 — 어제 이미 검증한 건 7일 쿨다운) → LLM 분류 → 큐 저장.
- 예산: 데이터랩 하루 후보 ≤40개 검증(호출 20회) 수준이면 충분. LLM은 통과분만이라 월 몇백 원.

## 7. 실패 모드와 대응

| 위험 | 대응 |
|---|---|
| 구글 RSS 포맷 변경/폐지 | 파싱 실패 시 경고 후 스킵(다른 채널 계속). 대안: signal.bz·네이트(간헐) |
| 자동완성 비공식 차단 | 가점 신호일 뿐 — 없어도 판정 가능하게 설계 |
| 데이터랩 상대값 드리프트 | 앵커 정규화(§4). 앵커 키워드 자체가 급변하면 앵커 교체 |
| 뉴스 오탐 | "X 뜻" 조건 + LLM 4-way에서 고유명사로 분류 → 자동 반려 |
| 검색광고 키 미발급 | A+C+D만으로 가동. B는 켜지면 절대량 가점으로 합류 |

## 8. 성공 지표

- 주간 관리자 큐 도달 후보 0~10개, **승인율 ≥50%** (문헌 달성치 58.7% 근처).
- 등록된 밈 중 "이 파이프라인이 처음 찾은 것"의 수 — 지금 0인 지표를 양수로 만드는 게 존재 이유.

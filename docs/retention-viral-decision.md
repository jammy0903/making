# 재플레이 · 전파(바이럴) 판단 문서

작성일: 2026-07-13 · 상태: **방향 확정(바이럴) · 레버 ①② 구현 완료, ③ 대기**

> 시작은 "메리트를 랜덤화하자"였지만, 파고 보니 진짜 물음은 **"왜 다시 할 이유가 없나"**였고,
> 결론적으로 **재플레이가 아니라 전파(바이럴)** 를 키우기로 방향을 잡았다. 이 문서는 그 판단 근거와
> 다음에 손댈 레버를 정리한다.

---

## 0. 결론 요약

1. **메리트 랜덤화는 이 문제의 답이 아니다.** (§1) 지금 스코프론 변주 이득 0 + 저작 품질 손실.
2. **이 장르는 "한 덱을 다시 하는" 게임이 아니다.** (§2) 밸런스·성격테스트는 1인 1덱 1회 + **공유로 전파**되는 구조.
3. **바이럴 방향 확정.** (§3) 재방문(리텐션)이 아니라 신규 전파를 먼저 키운다.
4. **최대 누수 = 공유 링크가 미리보기에서 안 팔린다.** (§4) OG 미리보기가 전부 똑같이 뜨고,
   결과는 클라이언트에서만 렌더돼 미리보기 봇이 결과를 못 본다.
5. **다음 작업 = ① SSR 동적 OG 텍스트부터.** (§5)

---

## 1. 왜 메리트 랜덤화는 답이 아닌가

`engine.ts` 기준 **merit은 결과·점수에 안 쓰이고 표시 전용**이다. 그래서 랜덤화해도 결과는 안 변하지만,
지금 스코프(기존 메리트를 편별 풀에 넣고 셔플)는 다음 이유로 손해다.

- **변주 이득 0**: 풀 크기 = 페널티 수(대부분 9=9, `tomato-vomit` 5=5). 시드 고정 비복원 셔플은
  **순열 한 번**일 뿐 → 매 플레이 결과가 지금과 동일. "랜덤"의 체감이 없다.
- **저작 품질 손실**: 현재 메리트는 *그 페널티의 같은 장면 뒷면*으로 저작됨.
  - `tomato-vomit` 주석: *"페널티/메리트는 같은 장면의 앞뒷면(쌍둥이)"* → 셔플 시 붕괴.
  - `dirty-partner` s9: "지갑 속 옛 사진" 페널티 ↔ "무심한 척해도 곁에 둔다는 게 들킴" 메리트 =
    그 페널티의 감정 반전. 딴 칸에 붙으면 헛소리.
  - 강도 곡선(2=가벼움 … 10=임종)도 셔플하면 무너짐.

**판정**: 관리 일원화가 목적이면 "메리트 별도 파일 + 강도 1:1 유지(랜덤 X)"가 안전한 리팩터.
진짜 변주가 목적이면 편별로 **강도 중립·페널티 비종속** 메리트를 9개보다 많이 새로 저작해야 비로소 의미.
어느 쪽이든 **재방문 문제의 핵심 레버는 아니다.**

---

## 2. 재정의 — "다시 하는 게임"이 아니다

- 구조: **완전 결정론 + 유한한 덱(약 12개)**. 같은 덱을 정직하게 하면 항상 같은 결과.
- 그런데 이건 결함이 아니라 **장르 특성**이다. 밸런스게임·성격테스트·버즈피드 퀴즈는:
  > **1인당 1덱 1회 → 결과 공유 → 친구 유입.** 재플레이가 아니라 **전파**로 산다.
- 따라서 "한 덱을 다시 하게 만들자"(=메리트 랜덤)는 **장르를 거스르는 방향**이고 품질 리스크만 남긴다.
- 봐야 할 지표는 **재플레이**가 아니라 **재방문 + 전파**.

### 이미 깔려 있는 자산 (코드 확인)
- 공유: 결과 링크 `?r=`, 도전 링크 `?vs=`, 인스타 이미지(PNG), PDF — `g/[deck]/+page.svelte`
- VS 비교(나 vs 상대) — 도전 링크로 상대가 같은 주제 플레이 후 나란히 비교
- **모두의 선택** 통계(첫인상 vs 최종, 라운드별 갈림) — `stats/+page.svelte`
- 캐릭터 카드(덱당 4종: 편별 극단/애매), 상위 N% 랭크
- 결과 localStorage 보관(최근 30) — `savedResults.ts`

→ **바이럴 재료는 이미 있다.** 약한 건 "퍼지는 입구"다.

## 3. 방향 결정

| 목표 | 내용 | 선택 |
| --- | --- | --- |
| 재방문(리텐션) | 기존 유저가 다시 옴(새 덱·알림·컬렉션) | |
| **신규 전파(바이럴)** | 한 명이 N명 데려옴(공유 입구·훅·미리보기) | **✅ 확정** |

바이럴 공식: **K = (1인당 공유 수) × (공유당 유입률)**. 재료(공유수)는 있으니
**공유당 유입률**을 먼저 끌어올린다.

---

## 4. 최대 누수 — 공유 링크가 미리보기에서 안 팔린다

한국 전파의 8할은 **카톡 링크 미리보기(OG)**. 그런데:

| 문제 | 사실 | 근거 |
| --- | --- | --- |
| OG가 전부 동일 | 덱/결과/도전 링크 모두 같은 정적 `og-default.png` + 앱 기본 제목으로 뜸 | `+layout.svelte:76-84` |
| 페이지가 OG를 안 덮어씀 | 덱 페이지 `<svelte:head>`가 **`<title>`만** 설정 | `g/[deck]/+page.svelte:337-339` |
| 봇이 결과를 못 봄 | 결과 `?r=`는 **클라이언트 onMount에서만** 파싱 → JS 안 도는 미리보기 봇은 결과를 영영 못 봄 | `+page.svelte:39-46` |
| 서버가 결과를 모름 | `+page.server.ts`는 덱만 로드, `?r=`/`?vs=`를 안 읽음 | `g/[deck]/+page.server.ts` |

**결과**: "🌞 그래도 여름 못 버리는 사람" 결과 링크나 홈 링크나 미리보기가 구분이 안 됨 →
궁금증 0 → 클릭 안 함 → **전파 첫 단계에서 사망.** 재료가 있어도 입구가 밋밋해서 안 퍼진다.

## 5. 레버 (효과/노력 순) — 다음 작업

### ① SSR 동적 OG 텍스트 — ✅ 완료(2026-07-13)
- `+page.server.ts`가 `?r=`/`?vs=`를 서버에서 읽어 결과 라벨 계산 → `og:title`/`og:description`/
  `twitter:*`/`description`을 SSR로 덮어씀(`+page.svelte` head). og:image는 아직 레이아웃 기본값.
- 3분기 검증(dev SSR):
  - 결과(`?r=000000`) → `🌞 아프리카에서 왔나요? 여름파`
  - 결정장애(`?r=010101`) → `🤷 어느 쪽도 못 버틴 결정장애 유형`
  - 도전(`?vs=111111`) → `🆚 여름 vs 겨울, 나랑 붙어볼래?`
- 참고: **DB 정본 덱이 코드와 판 수가 다름**(예: DB summer-winter=6판, 코드=10판). 기능은
  `roundsOf(로드된 덱)` 기준이라 무관하나, 콘텐츠 동기화는 별도 확인 필요.

### ② 결과별 동적 OG 이미지 — ✅ 완료(2026-07-13)
- `src/routes/og/[deck]/+server.ts`가 `?r=`/`?vs=`로 결과 카드를 **1200×630 PNG**로 렌더.
  파이프라인: **satori(HTML→SVG) → @resvg/resvg-js(SVG→PNG)**, 브랜드 픽셀폰트 Galmuri11.
- 폰트: satori가 woff2 미지원 → `static/fonts/*.woff2`를 **ttf로 변환**(fonttools)해 static에 추가,
  엔드포인트가 origin에서 fetch 후 모듈 캐시. satori가 이모지를 못 그려 **이미지 텍스트는 이모지 제거**,
  색·레이아웃으로 브랜딩(og:title 메타에는 이모지 유지).
- og:image 단일 소스화: `+page.server.ts`가 이미지 URL 계산 → `+layout.svelte`가 `page.data.og.image`로
  렌더(없으면 og-default.png). 페이지가 og:image를 또 넣어 태그가 2개 되는 문제 회피.
- 로직 공유: 결과 라벨/분기 판정은 `src/lib/game/share.ts`로 추출해 ①(텍스트)·②(이미지)가 공용.
- 검증(dev, 눈으로): 결과/도전/그냥덱 3분기 모두 1200×630 PNG 정상 렌더 + 한글 픽셀폰트 선명.
- 런타임: adapter-vercel 기본 **Node**(decksRepo가 node:crypto 물려 edge 불가). resvg-js 네이티브가
  Vercel Node 번들에 포함되는지는 실배포에서 최종 확인 권장(문제 시 @resvg/resvg-wasm로 교체).

### ③ 공유 문구 "자랑" → "도전" — 거의 공짜
- 현재 결과링크 메시지는 자기 결과 공유("내 결과를 그대로 봐요"). 전파는 **반대 유도**가 강함:
  "나는 여름인데 너는?" → 도전(`?vs=`)을 1순위 버튼으로, 랜딩 CTA도 "너도 나올지 봐".
- ① 작업하며 같이 손봄.

**추천 경로**: ① → (검증) → ② → ③ 반영. ①은 자체 완결적이라 먼저 넣고 효과를 본 뒤 ② 판단.

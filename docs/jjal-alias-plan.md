# 짤 검색 별칭(alias) 계획서

작성 2026-07-21. 대상: `/jjal` 짤 보관소 검색.

## 1. 문제

사용자 지적: **"GD라고 치면 아무것도 안 나오는데, 지드래곤이라고 치면 2장 나온다. 실제 지디 짤은 더 있다."**

2026-07-21 DB 실측(live 3,796장):

| 검색어 | 결과 |
| --- | --- |
| 지드래곤 | 2 (id 2895, 2896) |
| GD | **0** |
| 지디 | **0** |
| 권지용 | **0** |
| 빅뱅 | 1 — 그런데 **빅뱅이론(셸든)** 짤이다. 진짜 빅뱅 짤이 아니다 |

원인은 세 겹이다.

### 원인 1 — 별칭이 데이터에 없다 (이번에 해결)

id 2895의 keywords는 `['지드래곤','이런 거 싫어합니다','거부','질색','무한도전']`.
`GD`·`지디`·`권지용`이라는 문자열이 **DB 전체 어디에도 없다.**

검색 ①단계(keywords 정확 일치)와 ①'단계(caption 부분 일치)는 문자열 매칭이라 당연히 0건이다.
②단계 벡터 검색도 못 잡는다 — e5는 다국어 **의미 유사도** 모델이지 지식 베이스가 아니라서,
`GD`라는 두 글자가 `지드래곤`을 가리킨다는 **세상 지식**을 갖고 있지 않다.
즉 **임베딩을 아무리 잘 채워도 이 문제는 안 풀린다.** 별칭은 따로 알려줘야 한다.

### 원인 2 — 판정 단계가 대상을 이름으로 안 적었다 (별도 과제)

지드래곤 짤이 2장일 리 없다. 판정 프롬프트에 "알아보는 인물·작품이면 이름을 keywords에 넣어라"가
없었기 때문에, 캡션이 "파란 머리 남자가…" 식으로 대상을 특정하지 않고 끝난 짤이 다수 있다.
**없는 정보는 검색될 수 없다** — 이건 별칭으로 못 푼다. 재판정이 필요하다(6장).

### 원인 3 — 임베딩 미충전 (진행 중)

live 3,796장 중 `embedding IS NULL`이 2,491건이었다. 별개로 채우는 중.

## 2. 하기로 한 것 — 질의 확장(query expansion)

검색어를 받으면 **별칭 그룹을 찾아 동의어로 넓힌 뒤** 기존 검색을 돌린다.
데이터를 고치는 게 아니라 **질의를 고친다.**

```
"GD" → ["GD", "지드래곤", "지디", "권지용"]
      → 각각 keywords 정확 일치 + caption 부분 일치
      → 합집합(순서: 원본 질의 결과가 항상 먼저)
```

### 왜 이 방식인가

- **DB를 안 건드린다.** 3,796행 keywords에 별칭을 다 박아 넣으면 배열이 비대해지고,
  별칭이 추가될 때마다 전량 재적재 + 재임베딩이 필요하다. 사전은 배포 한 번으로 끝난다.
- **되돌리기 쉽다.** 잘못된 별칭은 사전 한 줄만 지우면 된다.
- **양방향이 공짜다.** 그룹 안의 어느 단어로 검색해도 나머지 전부가 걸린다.

### 왜 사전을 DB가 아니라 코드에 두는가

별칭은 사용자 데이터가 아니라 **우리가 관리하는 규칙**이다. 코드에 두면 리뷰·git 이력·롤백이
그대로 따라오고, 검색 경로에 DB 왕복이 한 번 줄어든다. 규모가 수만 그룹이 되면 그때 옮긴다.

## 3. 적용 범위 — 인물만이 아니다

사용자 요청: **"꼭 인물이 없어도"**. 별칭은 아래 전부를 대상으로 한다.

| 종류 | 예 |
| --- | --- |
| 인물 | 지드래곤 = GD, 지디, 권지용 |
| 프로그램·작품 | 무한도전 = 무도 / 놀면 뭐하니 = 놀뭐 |
| 캐릭터 | 잔망루피 = 루피 / 짱구는 못말려 = 짱구, 신짱구 |
| 감정·상태 | 현타 = 현실자각타임, 허탈 / 빡침 = 분노, 열받음, 짜증 |
| 상황 | 퇴근 = 칼퇴, 퇴근길 / 월요일 = 월요병 |
| 사물·소재 | 고양이 = 냥이, 냥, 고양 |
| 밈 표현 | 어쩔티비 = 어쩔, 어쩌라고 |
| 영/한 표기 | 리액션 = reaction / 짤 = 짤방 |

## 4. 동음이의 함정 (반드시 지킬 것)

`빅뱅` 사례가 그대로 경고다. **빅뱅(아이돌) ≠ 빅뱅이론(시트콤)**인데 문자열이 겹친다.

규칙:

- 그룹은 **의미가 같은 표현**만 묶는다. **연관어를 묶지 않는다.**
  - ✅ `지드래곤 = GD = 지디` (같은 대상의 다른 이름)
  - ❌ `지드래곤 = 빅뱅 = 아이돌` (연관일 뿐 같은 대상이 아니다 → 노이즈 폭증)
- 한 단어가 두 대상을 가리키면 **그 단어는 그룹에 넣지 않는다.** 확장을 포기하는 게 오검색보다 낫다.
- 한 글자 별칭 금지. 부분 일치에서 온갖 단어에 걸린다(기존 `q.length >= 2` 규칙과 같은 이유).

## 5. 구현

- `src/lib/server/jjalAlias.ts` — 그룹 배열 + `expandQuery()`. 그룹은 정규화 키로 역색인.
- `src/lib/server/jjal.ts` `searchJjals()` — 확장된 각 표현으로 ①·①' 수행, 원본 우선 순서로 합집합.
- 벡터 ②단계는 **원본 질의로만** 돈다. 별칭마다 임베딩을 부르면 HF 호출이 배로 늘고,
  의미 확장은 어차피 벡터가 이미 하는 일이다.
- 확장 상한을 둔다(그룹당 최대 8개). 사전 실수로 질의 하나가 수십 번 DB를 때리는 걸 막는다.

## 6. 별칭 발굴 — 전체 훑기

사용자 요청: **"3천여 장 다시 훑어서 별칭 더 추가하자."**

이미지를 다시 볼 필요는 없다. 별칭의 재료는 **이미 뽑아 둔 키워드**다.
live 3,796장에서 고유 키워드 **4,838개**(총 출현 18,910회, 1회만 등장 3,022개)를 집계했다.
이 목록을 나눠 훑으면서 "이 표현을 사람들이 달리 부르는 말"을 붙인다.
빈도 높은 것부터 처리한다 — 상위 500개가 전체 출현의 대부분을 차지한다.

**남은 과제(이 계획서 밖)**: 원인 2. 대상을 이름으로 적지 않은 짤을 찾아 재판정하는 일.
별칭 사전이 아무리 좋아도, keywords에 `지드래곤`이 없는 짤은 `GD`로도 안 나온다.

## 7. 하지 않을 것

- keywords 컬럼에 별칭을 직접 써 넣기 (재적재·재임베딩 비용 + 되돌리기 어려움)
- 연관어 확장 (`고양이` → `동물`). 검색 정밀도를 무너뜨린다
- 자동 생성 별칭을 검수 없이 반영. 동음이의 사고가 난다
